Fundamentos de Modelos Multimodales

Vision Encoders · Patch Embeddings · Projection Layers · Cross-Attention

Los modelos de IA multimodales procesan y razonan sobre múltiples tipos de datos de forma unificada: texto, imágenes, audio y video. Su arquitectura integra encoders especializados con un backbone de lenguaje (LLM) mediante capas de proyección.

💡 Principio clave: Un modelo multimodal no "ve" imágenes — convierte píxeles en secuencias de tokens que el transformer puede procesar igual que texto.

1.1 Vision Encoder y Patchification

La imagen se divide en parches (patches) cuadrados de tamaño fijo (16×16 o 32×32 px). Cada parche es aplanado, proyectado a un vector de dimensión d_model y enriquecido con un positional embedding 2D.

  Imagen 224×224 px
  ┌─────────────────────────────────────────────┐
  │  Patch  │  Patch  │  Patch  │  Patch  │ ... │
  │  16×16  │  16×16  │  16×16  │  16×16  │     │
  └─────────────────────────────────────────────┘
        ↓  Flatten + Linear Projection (768-dim)
  [t₁] [t₂] [t₃] [t₄] ... [t₁₉₆]   ← 196 tokens (224/16)²
        ↓  + Positional Embedding
  [CLS] [v₁] [v₂] ... [v₁₉₆]
        ↓  ViT Transformer Encoder (L layers)
  Representaciones visuales globales y locales

1.2 Projection Layers: Q-Former y Cross-Attention

El Q-Former (BLIP-2) comprime cientos de tokens visuales en un conjunto fijo de query tokens mediante cross-attention. Esto reduce el costo computacional de pasar vision features al LLM.

  Vision Encoder  →  Visual Features (196 × 768)
                               ↓
                    ┌──────────────────────┐
                    │       Q-Former       │  ← 32 Learned Queries
                    │   Cross-Attention    │
                    │   Self-Attention     │
                    │   Feed-Forward       │
                    └──────────────────────┘
                               ↓
                    32 Query Tokens (768-dim)
                               ↓
                    Linear Projection (LLM dim)
                               ↓
                    LLM (LLaMA / Mistral / Gemma)
                    [Q₁][Q₂]...[Q₃₂][Texto tokens]

1.3 Modalidades Soportadas

🖼️ Imagen estática 🎬 Video (frames) 🎵 Audio (mel spectrograms) 📄 PDF / Documentos 📊 Tablas y gráficas 🗺️ Screenshots GUI 🔬 Imágenes médicas 🛰️ Imágenes satelitales
1
Tokenización visual
La imagen se divide en N parches. Cada parche es procesado por el Vision Encoder (ViT/SigLIP/CLIP) produciendo embeddings densos.
2
Alineación modal
Un módulo de proyección (Q-Former, MLP simple o Cross-Attention) alinea el espacio visual con el espacio de texto del LLM.
3
Fusión en el transformer
Los tokens visuales se concatenan (o intercalan) con los tokens de texto. El LLM razona sobre la secuencia multimodal completa.
4
Generación condicionada
El modelo genera texto (o acciones) autoregressivamente, condicionado en el contexto visual y textual completo.

Arquitecturas VLA — Vision-Language-Action

Robótica Autónoma · RT-2 · OpenVLA · π0 · Bucle Percepción-Acción

Las arquitecturas VLA (Vision-Language-Action) extienden los modelos multimodales para producir no solo texto, sino acciones ejecutables en entornos físicos o digitales. Son el núcleo de la robótica moderna y los agentes autónomos.

🤖 Diferencia clave: Un VLM (Vision-Language Model) genera texto. Un VLA genera tokens de acción: coordenadas de robots, clics, comandos de teclado, waypoints.

2.1 Bucle de Percepción → Planificación → Acción

2.3 Representación de Acciones

Discreta (tokens)
RT-2 style
Las acciones se discretizan en bins y se codifican como tokens de texto. Simple pero limita la precisión.
Continua (MLP head)
OpenVLA style
Una cabeza MLP produce vectores de acción continuos a partir de los estados ocultos del LLM.
Diffusion Policy
Octo / Chi et al.
El LLM condiciona un proceso de difusión que genera trayectorias de alta calidad. Mayor costo inferencial.
Flow Matching
π0 style
Aprende un campo de flujo continuo entre ruido y acción. Más rápido que diffusion, alta fidelidad de movimiento.

Agentes de Control de GUI

Computer Use · OSWorld · Coordenadas Espaciales · OCR · Web Visual Navigation

Los agentes de control de GUI (Graphical User Interface) pueden interactuar con cualquier interfaz gráfica — navegadores, apps de escritorio, terminales — usando solo captura de pantalla como entrada y acciones de mouse/teclado como salida.

🖱️ Paradigma: Screenshot → Comprensión visual → Coordenadas (x,y) → Click/Type/Scroll. El agente nunca accede al DOM ni a APIs; opera como un humano frente a una pantalla.

3.1 Capacidades Clave

Grounding Visual
SoM / Set-of-Mark
El modelo recibe la screenshot con etiquetas numéricas superpuestas sobre elementos interactivos, reduciendo la tarea de localización a selección de número.
OCR Integrado
DocOwl / Qwen-VL
Extracción de texto estructurado desde la pantalla: tablas, formularios, menús, barras de dirección URLs.
Spatial Reasoning
Coordenadas relativas
El modelo produce coordenadas normalizadas [0,1] o absolutas en píxeles. Gemini y Claude usan formato [y1,x1,y2,x2] escalado a 1000.
Planning Jerárquico
Task → Subtask → Action
El agente descompone tareas complejas ("reserva un vuelo para mañana") en subgoals y acciones atómicas ejecutables.

3.2 Flujo de un Agente GUI Autónomo

1
Observación
Captura de screenshot (+ historial de acciones previas). Opcionalmente: acceso a árbol de accesibilidad (a11y tree) como texto auxiliar.
2
Comprensión y Grounding
El VLM identifica qué elementos son relevantes, lee texto en pantalla y localiza coordenadas del target (botón, input, link).
3
Generación de Acción
Produce JSON estructurado: {"action": "click", "coordinate": [450, 320]} o {"action": "type", "text": "hola mundo"}.
4
Ejecución y Verificación
El orquestador ejecuta la acción vía pyautogui / playwright. Se captura nueva screenshot para verificar que el estado cambió correctamente.

Evaluación y Benchmarks

MMMU · ChartQA · OSWorld · MMStar · MathVista · DocVQA

La evaluación de modelos multimodales requiere benchmarks especializados que cubran razonamiento visual, comprensión de documentos, interacción con GUI y ragionamiento espacial. Estos son los más relevantes en la literatura actual.

Benchmark Dominio Métrica Descripción Dificultad
MMMU Academia Accuracy 11.5K preguntas universitarias de 30 disciplinas con imágenes complejas (diagramas, fórmulas, gráficos) Muy Alta
ChartQA Gráficos Relaxed Accuracy Preguntas sobre gráficas de barras, líneas, pie charts. Requiere lectura de ejes, tendencias y comparaciones Alta
OSWorld GUI / Desktop Task Success Rate 369 tareas reales en 5 apps (Chrome, VS Code, LibreOffice, GIMP, OS) evaluadas en VM real Muy Alta
DocVQA Documentos ANLS Preguntas sobre documentos escaneados con OCR implícito: facturas, formularios, reportes Alta
MathVista Matemáticas Accuracy Razonamiento matemático combinado con imágenes: geometría, estadística, algebra visual Muy Alta
MMStar General Accuracy 1500 muestras curadas manualmente que requieren verdadero razonamiento visual (sin text leakage) Alta
VQAv2 VQA Clásico VQA Accuracy Preguntas de sentido común sobre imágenes de COCO. Punto de referencia histórico Media
SeedBench Múltiple Accuracy 19K MCQ en 12 dimensiones: comprensión de escenas, texto, relaciones espaciales, temporales Alta
📌 Referencia 2025: Gemini 2.5 Pro lidera en MMMU (72.6%), ChartQA (87.2%) y OSWorld (38.1%). GPT-4o es el segundo en la mayoría. Los modelos open-source (InternVL2, Qwen2-VL) cierran la brecha rápidamente.

Prompts & Code Snippets

Gemini Flash/Pro · GPT-4o · Claude 3.5 Vision · Multimodal APIs

Colección de snippets funcionales para integrar modelos multimodales en producción. Cada ejemplo incluye las llamadas de API más actuales con manejo de imágenes en base64 y URL.

6.1 Análisis de imagen con descripción

# Análisis de imagen con Gemini Flash 2.0
import google.generativeai as genai
import base64, pathlib

genai.configure(api_key="TU_API_KEY")
model = genai.GenerativeModel("gemini-2.0-flash")

# Desde archivo local (base64)
image_data = pathlib.Path("imagen.jpg").read_bytes()
image_part = {"inline_data": {"mime_type": "image/jpeg", "data": base64.b64encode(image_data).decode()}}

response = model.generate_content([
    image_part,
    "Describe esta imagen en detalle, identifica objetos y su posición espacial."
])
print(response.text)

# Desde URL pública
response_url = model.generate_content([
    {"file_data": {"mime_type": "image/jpeg", "file_uri": "https://ejemplo.com/img.jpg"}},
    "¿Qué actividad se está realizando en la imagen?"
])
# Análisis de imagen con Gemini vía REST API
IMAGE_B64=$(base64 -w 0 imagen.jpg)

curl -s -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=TU_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{
    \"contents\": [{
      \"parts\": [
        {\"inline_data\": {\"mime_type\": \"image/jpeg\", \"data\": \"$IMAGE_B64\"}},
        {\"text\": \"Describe esta imagen en detalle.\"}
      ]
    }]
  }" | jq '.candidates[0].content.parts[0].text'
// Análisis de imagen con Gemini — SDK JS
import { GoogleGenerativeAI } from "@google/generative-ai";
import fs from "fs";

const genAI = new GoogleGenerativeAI("TU_API_KEY");
const model = genAI.getGenerativeModel({ model: "gemini-2.0-flash" });

const imageData = fs.readFileSync("imagen.jpg");
const imagePart = {
  inlineData: { mimeType: "image/jpeg", data: imageData.toString("base64") }
};

const result = await model.generateContent([
  imagePart,
  "Describe esta imagen en detalle."
]);
console.log(result.response.text());

6.2 Análisis multimodal con GPT-4o

# GPT-4o: visión + texto con OpenAI SDK
from openai import OpenAI
import base64

client = OpenAI(api_key="TU_OPENAI_KEY")

with open("imagen.jpg", "rb") as f:
    b64 = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {"url": f"data:image/jpeg;base64,{b64}", "detail": "high"}
            },
            {"type": "text", "text": "Identifica todos los objetos y sus relaciones espaciales."}
        ]
    }],
    max_tokens=1024
)
print(response.choices[0].message.content)
# GPT-4o con imagen desde URL pública
curl https://api.openai.com/v1/chat/completions \
  -H "Authorization: Bearer TU_OPENAI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "image_url", "image_url": {"url": "https://ejemplo.com/img.jpg", "detail": "high"}},
        {"type": "text", "text": "Describe la imagen con detalle experto."}
      ]
    }],
    "max_tokens": 1024
  }'
// GPT-4o visión desde URL — JS moderno
import OpenAI from "openai";

const client = new OpenAI({ apiKey: "TU_OPENAI_KEY" });

const response = await client.chat.completions.create({
  model: "gpt-4o",
  messages: [{
    role: "user",
    content: [
      { type: "image_url", image_url: { url: "https://ejemplo.com/img.jpg", detail: "high" } },
      { type: "text", text: "¿Qué actividades se realizan en esta imagen?" }
    ]
  }],
  max_tokens: 1024
});
console.log(response.choices[0].message.content);

# Claude 3.5 Sonnet — Computer Use Agent
import anthropic, base64

client = anthropic.Anthropic(api_key="TU_ANTHROPIC_KEY")

with open("screenshot.png", "rb") as f:
    screenshot_b64 = base64.b64encode(f.read()).decode()

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=4096,
    tools=[
        {"type": "computer_20241022", "name": "computer",
         "display_width_px": 1920, "display_height_px": 1080, "display_number": 1},
    ],
    messages=[{
        "role": "user",
        "content": [
            {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": screenshot_b64}},

        ]

    betas=["computer-use-2024-10-22"]
)
